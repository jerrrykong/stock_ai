## 0.1 这份工程到底在做什么（一句话版）

它用**强化学习（Reinforcement Learning, RL）**&#x8BAD;练一个「交易机器人」，让它在 A 股日线数据上学会**何时买入、何时卖出、何时持有**，目标是获得尽可能高、且尽可能稳的收益。它**不直接预测明天的股价**，而是学习一套**决策规则**。

> 用一句生活化的话解释：我们不是在问「明天股票涨还是跌？」，而是在训练一个「操盘手」，告诉他每天看一眼行情后，决定今天该「买 / 卖 / 不动」。

## 0.2 机器学习的两大范式：监督学习 vs 强化学习

| 维度    | 监督学习（Supervised Learning）    | 强化学习（Reinforcement Learning） |
| ----- | ---------------------------- | ---------------------------- |
| 你给它什么 | 大量「题目 + 标准答案」（如：这张图是猫 / 不是猫） | 一个能交互的「环境」（如：模拟股市）           |
| 它学什么  | 从输入到输出的映射                    | 一套「行为策略」（什么状态下该做什么动作）        |
| 反馈形式  | 立刻知道对错（有标签）                  | 延迟、稀疏的「奖励」（赚了钱才给正反馈）         |
| 典型例子  | 垃圾邮件分类、人脸识别                  | 围棋 AlphaGo、游戏 AI、量化交易        |

- **监督学习**像做练习题：每道题旁边都写了正确答案，你照着纠偏。
- **强化学习**像学开车：没有人每毫秒告诉你「打方向盘对不对」，只有到了终点才知道「这趟开得好不好（奖励）」。智能体要在反复试错中，自己把「长远收益」与「当下动作」联系起来。

本项目用的是强化学习，具体是 **PPO（Proximal Policy Optimization，近端策略优化）** 算法。

## 0.3 强化学习的五个核心概念

强化学习通常被形式化为 **MDP（马尔可夫决策过程）**。理解下面五个词，你就懂了 80%：

| 概念          | 英文                  | 在本项目里的含义                                                    |
| ----------- | ------------------- | ----------------------------------------------------------- |
| **智能体**     | Agent               | 我们的「交易机器人」（本质是一个神经网络策略）                                     |
| **环境**      | Environment         | 模拟的 A 股市场（`TradingEnv`，在 `src/stock_ai/env/trading_env.py`） |
| **状态 / 观测** | State / Observation | 最近 N 天的行情特征窗口（如最近 20 天的收盘价、均线等）                             |
| **动作**      | Action              | 今天的决策：`0=持有 / 1=买入 / 2=卖出`                                  |
| **奖励**      | Reward              | 这一步带来的收益（含对「回撤大、交易太频繁、杠杆太高」的惩罚）                             |

**回合（Episode）**：从某一天开始，一路交易到数据末尾，这整个过程叫一个回合。训练就是让机器人一遍遍玩很多回合，逐渐变聪明。

**策略（Policy）**：智能体的「大脑」，输入一个状态，输出一个动作（或动作的概率分布）。本项目里策略 = 一个神经网络（`NumpyActorCritic`）。

**价值函数（Value）**：智能体对「当前这个状态未来能赚多少钱」的预估。PPO 同时训练策略和价值两部分，所以叫 **Actor-Critic（演员-评论家）** 架构。

> 类比：策略是「球员」，决定怎么踢；价值函数是「教练」，评估当前局势好不好。两者互相促进。

## 0.4 神经网络是什么（极简版）

本项目里策略和价值都是**神经网络**。你可以把它理解为一个「超级复杂的数学函数」：

```
输入（行情特征） ──> [ 隐藏层1 ] ──> [ 隐藏层2 ] ─> [ 输出层 ]
                                                              ├─> 动作概率（策略）
                                                              └─> 状态价值（价值）
```

- 它由很多**参数（权重 W 和偏置 b）**&#x7EC4;成，初值随机。
- **训练**就是不断调整这些参数，让「动作→奖励」的结果越来越好。
- 本项目默认用一个很小的两层全连接网络（`hidden = (64, 64)`，即两层各 64 个神经元），激活函数用 `tanh`。

> 你**不需要**懂微积分也能用这个项目。本项目甚至手写了一个不依赖 PyTorch 的纯 NumPy 训练器（见第 5 篇），就是为了让它「装不上深度学习库也能跑」。

## 0.5 PPO 是什么（最通俗的解释）

**PPO（Proximal Policy Optimization，近端策略优化）** 是目前最常用、最稳定的强化学习算法之一（ChatGPT 背后的 RLHF 也用到它）。

它的核心思想可以概括为三步：

1. **试玩收集经验**：让当前策略在环境里玩一段时间，记录下「看到了什么状态、做了什么动作、拿到多少奖励」。
2. **评估好坏（优势函数）**：用 GAE（广义优势估计）算出——「这一步动作，比平均水平好多少？」好的动作就多奖励，差的就少奖励。
3. **小心地改策略**：用「**裁剪（clip）**」机制更新策略参数，**只允许策略小幅改变**，避免一次改太猛导致训练崩溃。

> 「Proximal（近端）」的含义正是「每次只动一点点，别离旧策略太远」。这是 PPO 比其他算法稳的关键。

## 0.6 Gymnasium 是什么

**Gymnasium**（原 OpenAI Gym）是强化学习领域的「标准接口规范」。它定义了环境该怎么写：

- `reset()`：把环境重置到初始状态，返回第一帧观测。
- `step(action)`：执行一个动作，返回 `(观测, 奖励, 是否结束, 是否截断, 额外信息)`。
- `observation_space` / `action_space`：声明观测和动作长什么样。

本项目自己实现了符合这个规范的 `TradingEnv`（交易环境），这样就能直接套用现成的 PPO 训练框架。

## 0.7 前视偏差 / 数据泄漏 / Walk-forward（非常重要！）

这是量化项目最容易翻车的地方，本项目花了很大力气防止它：

- **前视偏差（Look-ahead bias）**：用到了「未来才知道的信息」去做「当时的决策」。比如用全样本均值去标准化第 1 天的数据，就等于偷偷看了未来——这会让你回测赚翻，实盘亏死。
- **数据泄漏（Data leakage）**：训练时用到了测试集的信息。
- **Walk-forward（滚动前向）**：把数据**严格按时间顺序**切成「训练集 → 验证集 → 测试集」，绝不打乱，且训练/测试之间留一段 **embargo（隔离带）** 防止边界泄漏。

本项目的关键设计：**归一化的统计量（均值/标准差）只在训练窗口上 fit 并冻结**，之后所有环节（训练、回测、预测）都复用这套冻结值，绝不允许重新计算（详见第 3 篇）。

**扩展阅读**

- 维基百科 · 前视偏差（Look-ahead bias）：<https://en.wikipedia.org/wiki/Look-ahead_bias>
- Walk-forward 分析介绍：<https://en.wikipedia.org/wiki/Walk_forward_optimization>

## 0.8 几个你会反复看到的术语（速查表）

| 术语                 | 含义                                 |
| ------------------ | ---------------------------------- |
| **MDP**            | 马尔可夫决策过程，RL 问题的数学框架                |
| **Policy / 策略**    | 智能体的决策函数（输入状态→输出动作）                |
| **Actor-Critic**   | 同时训练「策略（Actor）」和「价值（Critic）」的架构    |
| **GAE**            | 广义优势估计，衡量某动作相对平均有多好                |
| **Clip（裁剪）**       | PPO 的核心：限制策略更新幅度                   |
| **Reward shaping** | 奖励塑造，给奖励加惩罚项引导训练（如惩罚频繁交易）          |
| **Episode / 回合**   | 从开始到结束的一次完整交互过程                    |
| **Rollout**        | 让策略在环境里跑一段收集经验                     |
| **On-policy**      | 用当前策略收集的数据只训练当前策略（PPO 是 on-policy） |
| **Backtest / 回测**  | 用历史数据检验策略表现                        |
| **Sharpe / 夏普比率**  | 风险调整后收益的常用指标                       |
| **Drawdown / 回撤**  | 从最高点回落的最大幅度                        |
| **Walk-forward**   | 按时间顺序滚动切分训练/测试                     |
| **Embargo**        | 训练/测试之间的隔离交易日，防泄漏                  |
