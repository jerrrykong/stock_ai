# 第 2 篇：数据层（data）—— 行情从哪来、怎么存、怎么防坑

> 本篇解读 `src/stock_ai/data/` 子包：它负责把真实 A 股日线行情拉下来、存好、增量刷新，并处理一个很容易踩雷的问题——**复权口径**。这是整个流水线的「原材料车间」。

---

## 2.1 数据层在流水线中的位置

```
网络 API  ──>  data/loader (多源 fallback)  ──>  data/raw/*.parquet  ──>  samples 层
                                            └─>  data/raw_hfq/*.parquet (训练专用后复权)
```

数据层只做一件事：**把不可靠、口径不一、会限流的网络数据，变成可靠的本地 parquet 缓存**。它不关心特征、不关心训练，下游谁用谁取。

---

## 2.2 标准数据契约（schema.py）

所有写入磁盘的行情都必须过 `validate_frame` 这道关。核心约束（来自 `data/schema.py`）：

- **标准列顺序（强制）**：`["date","open","high","low","close","volume","amount","adj_factor"]`
- **数据类型**：`date → datetime64[ns]`，其余 `float64`
- **清洗规则**：列补齐/重排 → 按 `date` 升序 → 去重（保留最后一条）→ **剔除非正价/NaN 行** → `amount/adj_factor` 缺失用 0/1 填充

`SymbolInfo` 记录每只股票的缓存元信息（起止日期、行数、来源、更新时间、复权口径 `adjust`），汇总进顶层 `data/meta.json`。

> 为什么这么严？因为下游训练对数据质量极其敏感，一行脏数据（比如负价）就可能让模型学偏。把校验集中在 `validate_frame` 一处，是最省心的做法。

---

## 2.3 多源 fallback 机制（关键设计）

不同数据源各有优缺点（有的快但限流严，有的慢但能一次取全历史）。本项目把它们做成**适配器（Adapter）**，并自动按顺序 fallback。

### 数据源注册表与 fallback 链
- 数据源注册表在 `loader.py` 的 `_SOURCE_FACTORIES`（**唯一真源**），派生出 `SUPPORTED_SOURCES` 白名单，避免「白名单」与「实际构造」不一致。
- **Fallback 链顺序**：`_FALLBACK_CHAIN = ("akshare","tencent","eastmoney","sina")`，构造时把你指定的 `source`（默认 akshare）置首位，再追加其余，最后追加 `synthetic`（离线兜底）。

### 各数据源实测特性（README §3.6 实测结论）

| 数据源 | 复权支持 | 单次返回 | 风控 | 备注 |
|---|---|---|---|---|
| `tencent` | qfq / hfq / none | 约 800 根（自动分页） | ⚠️ 连续快拉约 150 只后返回 501 | 项目原主源 |
| `sina` | **仅 none** | **全部历史**（一次请求） | 未见 | **批量拉取推荐** |
| `eastmoney` | none | — | 部分网络会断连 | 不可依赖 |
| `akshare` | — | — | 依赖上述接口 | 可选依赖，可能未安装 |
| `synthetic` | 忽略 | 确定性随机游走（GBM） | 无 | 离线兜底 |

### 拉取逻辑（`fetch_symbol`）
遍历 `self.sources`，逐个调用 `src.fetch()`，成功即返回并记下来源；**全失败才抛 `DataSourceError`**。

> 设计亮点：非法 `--source` 值会被 `ConfigError` 明确拒绝（绝不静默接受）；真实源全部失败时**默认不写合成假数据**（`--allow-synthetic` 默认关），失败标的记入 `fetch_failed.txt` 供下轮补拉。这是「绝不污染训练集」的原则体现。

## 2.4 缓存命中与增量刷新（cache.py / loader.py）

### 缓存契约
落盘位置：`data/raw/<symbol>.parquet` + 顶层 `data/meta.json`。用 `sanitize_filename` 处理 Windows 非法字符。

### 缓存命中（`_covers`）
只有当「缓存区间覆盖请求区间（边界容差 5 天）**且复权口径一致**」时才命中，否则全量重拉。

### 复权口径隔离（重要！）
不同复权口径（qfq/hfq/none）的旧缓存**绝不混用**。如果切换口径，会**全量重拉**并尽量保留既有区间（`min(缓存起日, config.start)`），避免出现「qfq 老数据 + hfq 新数据」的口径污染。

### 增量刷新（`refresh_symbol`）
读缓存 → 以 `max(date)+1` 为起点拉增量 → `merge_incremental`（拼接+去重+升序）。口径变更时退化为全量重拉。

### 缺交易日检测
`cache.find_gaps(df, freq="B")` 用工作日日历检测缺失交易日，返回缺失日期列表，方便你发现数据断层。

## 2.5 复权口径：为什么这是个坑

**背景知识：什么是复权？**
股票会分红、送股，导致「不复权」价格出现断崖式跳空（比如 10 送 10 后股价直接腰斩，但这不是真的跌了 50%）。为了让历史价格连续可比，就有了：
- **前复权（qfq）**：以最新价为基准，向前调整历史价。可能出现**早年负价**（高分红股 early years）。
- **后复权（hfq）**：以上市首日为基准，向后累积调整。本项目实测**无负价**，可取完整历史。
- **不复权（none，默认）**：原始成交价。

### 实测坑（README §3.6 已记录）
- 腾讯**前复权**对高分红股（如 600519 贵州茅台）早年会返回**负价**（2013 年 close ≈ -189），这类行被 `validate_frame` 剔除，导致茅台用 qfq 只能保留 2016-07 起约 2060 行；而 none / hfq 不受影响，可取满 2012 年起约 3000 行。
- 新浪源与腾讯源价格逐日一致、`volume` 口径一致（均为「股」），可互为 fallback。新浪在 `--adjust qfq|hfq` 时会**明确报错并自动改用其它源**（不静默给错口径）。

**本项目建议**：默认 `none`（不复权）即可拿完整原始历史；要复权序列用 **`--adjust hfq`**（无负价、完整）。

## 2.6 训练专用后复权（hfq.py）—— 两套价格隔离

这是一个容易混淆但很关键的设计：

- `data/raw` 存**不复权**真实价（供撮合成交，保证交易用真实价格）。
- `data/raw_hfq` 存**独立的后复权缓存**（供特征/训练信号，价格连续更好学）。
- 两条路径**完全隔离**：`fetch-hfq` 绝不覆盖 `data/raw`。
- 严格撮合训练会**同时读两套价格**，按交易日 inner join 对齐（`env/strict_env.py` / `corporate_action_env.py`）。

`hfq.py` 还做了**强校验**：后复权出现非正价**默认直接抛错**（不像 `validate_frame` 静默剔行），并输出除权跳空修复统计（`|日收益|>11%` 次数在 hfq 侧显著减少，说明跳空已修复）。拉取支持限速（`--throttle`）、批间休息、连续失败判风控冷却、逐只容错、进度可查。

## 2.7 公司行为账本（corporate_actions.py，概述）

分红、送转股会真实改变账户权益，本项目用 `CorporateActionLedger` 管理**显式审阅过的账本**：
- 严格字段校验 + 对原始字节算 `sha256`。
- 核心约束：`coverage.status=="verified"`、`kind` 仅支持 `distribution`、送转股份必须带 `listing_date`。
- **不联网、不从复权比值推断事件**（避免假阳性）。
- `corporate_action_sources.py` 只负责「采集巨潮原响应 + 未审阅候选」，**绝不输出 verified 账本**，也禁止写入正式账本目录（只归档到 `outputs/`）。

> 这部分属于「公司行为 v2」，在大规模训练（第 8 篇）中使用，且 README 明确说明「本次未启动训练、未补齐 300 股票全历史账本」。属于前沿/实验特性，使用时要注意其「先核验账本，再训练」的强约束。

## 2.8 数据层关键文件清单

| 文件 | 职责 |
|---|---|

| `data/corporate_actions.py` | 公司行为账本（分红送转） |

## 2.9 本篇小结

- 数据层是「原材料车间」：把不可靠网络数据变成可靠的本地 parquet。
- **多源 fallback + 强校验 + 口径隔离**是其三大护城河。
- **复权口径**是真实世界的坑：默认 `none`，要复权用 `hfq`；两套价格（真实价 / 后复权）严格隔离。
- 失败单只不中断整批，离线可用 `synthetic` 兜底。
