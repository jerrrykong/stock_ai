# 第 1 篇：架构总览与运行方式

> 本篇从全局视角解读 `stock_ai` 的软件架构：分层设计、命令树、模块间如何通信、后端如何自动降级，以及如何在本机跑通。读完你会对「代码是怎么组织起来的」有完整认识，后续各篇再逐层深挖。

---

## 1.1 一句话定位

`stock_ai` 把「**数据获取 → 样本构建 → RL 训练 → 回测评估 → 未知数据预测**」做成一条**可复现、可分工、每一环节独立可运行**的 A 股量化交易流水线。

核心代码在 `src/stock_ai/`，按职责分为 8 个子包：

```
src/stock_ai/
├── config/      # 配置对象与加载器（AppConfig + ConfigLoader）
├── utils/       # 公共工具（日志/异常/哈希/重试/种子/IO）
├── data/        # 多源数据拉取 + parquet 缓存 + 增量刷新
├── samples/     # 特征工程 + 防泄漏归一化 + walk-forward 切分
├── env/         # 交易环境（Gymnasium.Env）+ A 股规则 + 奖励
├── train/       # 训练层（SB3 封装 + 纯 NumPy PPO 兜底 + 工厂）
├── eval/        # 回测 + 指标 + 绘图
├── infer/       # 未知区间预测
└── cli/         # click 子命令树（统一入口）
```

> 此外还有一个较新的 `scale/` 子包（大规模沪深300×年度单元训练编排，见第 8 篇），它在上述 6 条主命令之上叠加，不影响任何既有命令。

**分层依赖铁律**（来自 README §5）：
```
cli → train/eval/infer → env/samples → data → config/utils
```
即**下层绝不 import 上层**。例如 `data/` 永远不会去 import `train/`；`samples/` 不会去 import `cli/`。

## 1.3 模块间靠「文件契约」通信（而非内存对象）

这是本项目最重要的工程决策之一：**命令与命令之间不通过 Python 对象传递数据，而是通过磁盘上的文件**。好处是每个环节都能单独运行、单独调试、单独复现。

| 环节 | 输入 | 输出 |
|---|---|---|
| `data fetch` | 网络 API | `data/raw/<symbol>.parquet` + `data/meta.json` |
| `data fetch-hfq` | 网络 API | `data/raw_hfq/<symbol>.parquet` |
| `sample build` | parquet | `data/samples/{train,val,test}.npz` + `meta.json` |
| `train` | `train.npz` | `models/<algo>_<ts>.zip` + sidecar json + `logs/<run>/curve.png` |
| `backtest` | 模型 + `test.npz` | `reports/backtest_<ts>.json` + `equity_<ts>.png` |
| `predict` | 模型 + `meta.json` + `data/raw` | `reports/predict_<ts>.{csv,json}` |

> 这套契约在 `src/stock_ai/utils/io.py` 中集中实现（`read/write_parquet`、`read/write_npz`、`read/write_json` 等），所有读写显式 UTF-8，保证跨平台不乱码。

## 1.5 CLI 命令树

统一入口：`python -m stock_ai <command>`（安装后也可用 `stockai <command>`）。`cli/main.py` 是一个 `click.Group`，延迟导入各子命令避免循环依赖。

| 命令 | 作用 | 映射到哪个层 |
|---|---|---|
| `data fetch / refresh / info / fetch-hfq / hfq-status` | 数据拉取与缓存 | `data.loader` / `data.hfq` |
| `sample build` | 构建 walk-forward 样本 | `samples.builder` |
| `train` | 训练模型 | `train.train_cli` |
| `backtest` | 回测评估 | `eval.backtester` |
| `predict` | 未知区间预测 | `infer.predictor` |
| `doctor` | 环境自检 | 全局 |
| `scale ...` | 大规模训练编排（第 8 篇） | `scale.*` |

每个子模块还有独立入口（便于分工调试），例如：
```bash
python -m stock_ai.data.fetch_cli fetch --symbols 600519 --start 20230101 --end 20231231
python -m stock_ai.samples.build_cli --symbols 600519 --window 20
python -m stock_ai.train.train_cli --algo ppo --timesteps 5000
python -m stock_ai.eval.backtest_cli --model models/ppo_x.zip
python -m stock_ai.infer.predict_cli --model models/ppo_x.zip --symbols 600519
```

## 1.6 后端自动选择（主后端 / 兜底后端）

强化学习通常需要 PyTorch + Stable-Baselines3，但很多环境（尤其是小内存远程机）装不上。本项目设计了**两档后端，自动降级**：

| 优先级 | 后端 | 触发条件 |
|---|---|---|
| L0 | **SB3 PPO**（主） | `stable_baselines3` 与 `torch` 都可导入 |
| L2 | **纯 NumPy PPO**（兜底） | 上述不可用，或显式 `--backend numpy` |
| L3 | 规则基线 | `backtest` 中的 buy&hold 始终可用 |

两者共享统一接口（`learn / predict / save / load`，定义在 `train/base.py` 的 `Enrollment` 协议），并共用同一套 `models/*.zip` 文件契约：
- SB3：原生 `model.save()` 的 zip
- NumPy：内部打包 `weights.npz` + `hparams.json` + `backend.json` 的 zip

`backtest` / `predict` 通过读取 zip 内的 `backend.json` 自动识别后端并正确加载。**即使你完全不懂深度学习，纯 NumPy 后端也能保证全链路跑通**——这正是 `ppo_numpy.py` 存在的意义（详细见第 5 篇）。

> 选择逻辑在 `train/factory.py` 的 `TrainerFactory.create()`：非法 `--algo` / `--backend` 会**明确报错**，绝不会被 auto 回退链路静默吞掉。

## 1.7 配置优先级

```
CLI 参数  >  YAML 配置  >  代码默认值
```

- 配置对象集中在 `config/schema.py`（`AppConfig` 及其子 dataclass：`DataConfig` / `SampleConfig` / `EnvConfig` / `TrainConfig` / `PathConfig` / `ScaleConfig`）。
- `config/loader.py` 的 `ConfigLoader` 负责：YAML → `AppConfig` → 环境变量覆盖 → 路径解析。
- 任意层只接收「配置对象」，不直接解析命令行（单一职责）。

## 1.8 可复现性设计（这是科研/量化项目的命门）

本项目把「可复现」当成硬指标，三道保险：

1. **固定种子**：全局 `--seed`（默认 42）通过 `utils/seed.py` 的 `set_global_seed` 对齐 `random` / `numpy` / `PYTHONHASHSEED` / 可选 `torch`。
2. **数据快照哈希**：`sample build` 对**所有 raw parquet 字节**计算 `sha256`（按文件名排序后依次 update，见 `utils/hashing.py` 的 `sha256_files`），写入 `samples/meta.json` 的 `data_hash`。
3. **复现链**：`meta.data_hash` → 写入模型 sidecar json → 回填 `backtest` 报告。同数据 + 同参数 = 同 `data_hash` = 同结果。

> 你可以亲自验证：连续两次 `sample build --symbols 600519`，`data_hash` 必须完全一致。

## 1.9 如何在本机跑通

### 一键搭建（Windows PowerShell）
```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_env.ps1
```

### 手动安装（等效，使用项目隔离的 venv）
```bash
# 用项目自带的 Python 解释器
PY="C:\Users\jerrykong\.workbuddy\binaries\python\envs\default\Scripts\python.exe"
& $PY -m pip install "numpy>=2.1,<2.6" "pandas>=2.2,<3.0" "scipy>=1.14" \
    "pyarrow>=17,<22" "click>=8.1" "pyyaml>=6.0" "matplotlib>=3.9" \
    "requests>=2.32" "tqdm>=4.66" "gymnasium==1.1.1"
& $PY -m pip install "torch>=2.6,<2.8" --index-url https://download.pytorch.org/whl/cpu   # 可选
& $PY -m pip install "stable-baselines3>=2.6,<2.9"   # 可选
& $PY -m pip install -e .
& $PY -m stock_ai doctor
```

### 端到端 6 步
```bash
# 1. 拉数据（新浪源批量推荐，无风控）
python -m stock_ai data fetch --symbols 600519 --start 20120101 --end 20241231 --source sina
# 2. 建样本
python -m stock_ai sample build --symbols 600519 --window 20
# 3. 训练（后端自动选；--backend numpy 强制纯 NumPy）
python -m stock_ai train --algo ppo --timesteps 200000
# 4. 回测
python -m stock_ai backtest --model models/ppo_xxx.zip
# 5. 预测未知区间
python -m stock_ai predict --model models/ppo_xxx.zip --symbols 600519 --start 20250101
# 6. 全景摘要
python -m stock_ai status
```

> Linux / 远程部署：用等价的 `run.sh` 与 `scripts/setup_env.sh`，产物与文件契约完全一致（详见 README §3）。

## 1.10 本篇小结

- 代码按 `config/utils → data → samples/env → train/eval/infer → cli` **严格分层**，下层不依赖上层。
- 模块间靠**文件契约**（parquet / npz / zip / json）通信，每个环节可独立运行。
- 训练后端**自动降级**（SB3 → 纯 NumPy），保证无深度学习库也能跑。
- 通过**固定种子 + 数据哈希 + 复现链**三重保险保证可复现。
