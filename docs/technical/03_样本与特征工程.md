# 第 3 篇：样本与特征工程（samples）—— 把原始行情变成 AI 能吃的「菜」

> 本篇解读 `src/stock_ai/samples/` 子包。原始行情是「生肉」，AI 模型需要的是「切好、调好味、按时间摆盘的菜」。这一层干的就是这个：算技术指标、标准化、按时间切分、打包成 npz。其中**防泄漏归一化**和 **walk-forward 切分**是本项目最值得细读的设计。

## 3.2 特征工程（features.py）：从 OHLCV 到技术指标

**背景知识：什么是特征（Feature）？**
模型不能直接「看 K 线图」，它需要**数值化的、有信息量的输入**。本项目把每天的市场状态表示成一组数字，分两类：

- **基础列（BASE_COLUMNS）**：`open / high / low / close / volume`（开盘/最高/最低/收盘/成交量），直接来自原始行情。
- **派生列（DERIVED_COLUMNS）**：用历史数据算出来的技术指标：
  - `ma5 / ma10 / ma20`：5 / 10 / 20 日**移动平均线**（均价的平滑趋势）
  - `momentum`：**动量** = 近 10 日收益率（`close_t / close_{t-10} - 1`），衡量涨跌速度
  - `volatility`：**波动率** = 近 20 日对数收益滚动标准差，衡量震荡剧烈程度
  - `volume_ratio`：**量比** = 当日量 / 近 5 日均量，衡量放量还是缩量

### 关键约束：只用「过去能看到的信息」
`build_indicators` 里所有指标都用 `rolling`（滚动窗口）或 `pct_change` 计算，**只用 t 及之前的数据**，绝不居中、不打乱。例如 `ma20` 用 `close.rolling(20)`，第 t 天的值只依赖前 20 天——这保证了**没有前视**。

> 这是一个典型错误示范的反面教材：如果某指标用「未来 10 天均值 - 过去 10 天均值」，那就偷偷看了未来，回测会虚假暴利。本项目从函数层面杜绝了这种写法。

## 3.3 防泄漏归一化（normalizer.py + features.fit/transform）—— 全项目最重要的防线

**背景知识：为什么要归一化（Normalization）？**
不同特征的量纲差异巨大：`close` 可能上千（股价），`volume_ratio` 在 1 附近，`momentum` 是个小数。直接喂给神经网络，量纲大的特征会主导训练。所以要把它们变成「均值≈0、标准差≈1」的标准分布。

**但是！归一化统计量（均值/标准差）必须在哪算？**
这是本项目严防死守的点：

```
❌ 错误做法：用全部数据（含测试集）算 mean/std，再标准化每一天
   → 测试集的信息泄漏进了训练 → 回测虚假繁荣
✅ 正确做法（本项目）：
   1. 在 sample build 时，ONLY 用【训练窗口】的数据 fit 出 mean/std
   2. 把这套 mean/std 冻结成 NormalizerState，写入 meta.json
   3. 训练 / 回测 / 预测 一律复用这套冻结值，绝不重新 fit
```

代码体现（`features.py`）：
- `fit(df)`：仅用传入的 DataFrame（调用方保证是训练窗口）算 `mean/std`，返回冻结的 `NormalizerState`。
- `transform(df, state)`：**用外部传入的冻结 state 标准化，绝不重新计算**。如果特征列不匹配，直接抛 `ArtifactError`。

`NormalizerState`（`normalizer.py`）是个轻量 dataclass，存 `mean / std / columns / data_hash`，可 JSON 序列化。

> 这条铁律在代码里反复出现（K9 标记），是「可复现 + 无泄漏」的基石。预测阶段（`infer/predictor.py`）如果没拿到冻结的 `NormalizerState`，会直接报错，不允许拿新数据偷偷重 fit。

## 3.4 walk-forward 时间切分（split.py）—— 第二道防线

**背景知识：为什么不能随机切分？**
普通机器学习常随机分训练/测试集。但时间序列（股价）有**时间顺序和自相关**，随机切分等于把「未来的样子」混进训练。正确做法是**按时间顺序**切，并且训练/测试之间留隔离带。

`walk_forward_split(dates, train_range, test_range, embargo_days)`：
1. `train_idx`：日期落在 `[train_start, train_end]` 的位置索引
2. `test_idx`：日期落在 `[test_start, test_end]` 的位置索引
3. **embargo（隔离带）**：从训练尾部裁掉 `embargo_days`（默认 5）个交易日，防止边界泄漏
4. **硬校验零重叠**：若 train/test 有任何交集，直接抛 `ConfigError`

另外还有 `val`（验证集）：从训练窗口尾部按 `val_ratio`（默认 0.15）切出，**与训练集不重叠**，用于训练中监控。

> 一句话：训练永远在「更早的时间」，测试永远在「更晚的时间」，中间还留缓冲。这样回测出的结果才可信。

## 3.5 滑窗观测矩阵（make_obs_matrix）—— 把「时间」塞进输入

神经网络一次吃一个「状态」。本项目的状态定义为：**最近 `window`（默认 20）天的特征窗口**。

`make_obs_matrix` 把 `(T, n_features)` 的特征矩阵，滑窗拼成 `(T, window, n_features)` 的张量：
- 第 t 个样本用 `feat[t-window+1 : t+1]`（含当天）
- 前 `window-1` 天用**前端复制填充**（用首行复制），保证输出行数与输入对齐，便于和 dates/prices 对应

举个直观例子（`window=3`，假设只有 5 天）：
```
原始特征行:  d1  d2  d3  d4  d5
观测窗口:    [d1,d1,d1]  [d1,d2,d3]  [d2,d3,d4]  [d3,d4,d5]  [d4,d5,d5]
```
（前 2 天不足 3 天，用第一天复制补齐；这里末段示意，实际代码前端填充）

## 3.6 样本打包契约（schema.py + builder.py）

`SampleBuilder.build_all()` 把以上步骤串起来：

1. 校验训练/测试区间合法
2. 读所有 raw parquet
3. 算 `data_hash`（raw 字节 sha256，见第 1 篇 §1.8）
4. **仅用训练窗口 fit 出冻结 `NormalizerState`**
5. 用冻结 state 分别构建 train/val/test 三个 `SampleSplit`
6. 组装 `SampleBundle`，写盘

### 输出文件（文件契约）
- `data/samples/train.npz` / `val.npz` / `test.npz`
- `data/samples/meta.json`（含 `normalizer.to_dict()`、`data_hash`、`feature_names`、`window`、`train_range`、`test_range`、`embargo_days` 等）

### SampleSplit 结构
| 字段 | 含义 |
|---|---|
| `obs` | `(T, window, n_features)` float32 观测张量 |
| `dates` | `(T,)` 日期 |
| `symbols` | `(T,)` 股票代码 |
| `prices` | `(T,)` float64 真实收盘价（供撮合/结算） |
| `n_steps` / `n_features` | 步数 / 特征数 |

> `SampleBundleStub` 是一个仅含 meta 的轻量对象，供 `predict` 复用冻结 `NormalizerState`，避免重新加载全部 npz。

## 3.7 这一层的工程亮点总结

1. **无前视的特征**：所有指标只用历史数据（rolling / shift）。
2. **冻结归一化**：mean/std 只在训练窗口 fit，全链路复用，杜绝泄漏。
3. **严格 walk-forward + embargo**：训练早于测试，且有隔离带，零重叠硬校验。
4. **`data_hash` 锚定**：原始数据指纹贯穿到模型与回测，保证可复现。
5. **清晰的 npz + meta.json 契约**：下游直接按文件读取，无需耦合。

---

## 3.8 本篇小结

- 样本层把「生肉行情」切成 AI 能吃的「标准菜」：算技术指标 + 标准化 + 滑窗 + 时间切分。
- **防泄漏**是核心：`NormalizerState` 冻结、walk-forward + embargo 双保险。
- 输出 `data/samples/*.npz + meta.json`，下游（训练/回测/预测）按文件读取。
