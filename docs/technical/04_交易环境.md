# 第 4 篇：交易环境（env）—— 强化学习的「舞台」与 A 股规则

> 本篇解读 `src/stock_ai/env/` 子包。如果说智能体（策略网络）是「演员」，那么**环境**就是「舞台 + 剧本 + 裁判」。它定义了：演员每步能看到什么（状态）、能做什么（动作）、做的后果如何（账户变化）、以及裁判给的打分（奖励）。本篇还会详解 A 股特有的交易规则如何在代码里落地。

---

## 4.1 三个文件，各司其职

| 文件 | 角色 | 关键内容 |
|---|---|---|
| `trading_env.py` | **舞台与裁判**（Gymnasium.Env） | `reset` / `step` / 账户状态 / 观测 / 奖励调用 |
| `rules.py` | **A 股规则纯函数** | T+1、涨跌停、停牌、滑点、佣金、印花税（无副作用，易测） |
| `rewards.py` | **奖励计算器** | 多目标结构化奖励（收益 − 惩罚项） |

设计亮点：**规则全部写成纯函数**（K14 标记），不依赖全局状态，所以可以用单元测试精确验证「T+1 当天买入不能卖」「涨停不能买」等，而不必启动整个环境。

---

## 4.2 状态 / 动作 / 奖励（回顾第 0 篇概念）

- **状态（观测）**：最近 `window` 步的归一化特征窗口 + 账户标量（仓位比例）。
- **动作**：离散 `0=持有 / 1=买入 / 2=卖出`（或连续目标仓位，由 `action_mode` 控制）。
- **奖励**：由 `RewardCalculator` 计算（见 §4.6）。

---

## 4.3 TradingEnv 的核心循环（trading_env.py）

环境继承自 `gymnasium.Env`，实现标准接口：

### `reset(seed, options)` → `(obs, info)`
把环境重置到起点：账户回到初始现金 `initial_cash`、持仓清零、索引归零、历史峰值重置。返回第一帧观测。支持 `options={"start_idx": ...}` 指定起点。

### `step(action)` → `(obs, reward, terminated, truncated, info)`
这是环境的心脏，每调用一次 = 模拟「交易一天」。简化流程：

```
1. 取当前价、昨收
2. 标的分界处理：若进入新标的的第一天，先强制平仓上一标的遗留持仓（避免跨标的套利失真）
3. 判定是否停牌、T+1 冻结天数
4. 执行动作：
   - 买入：检查 can_buy → 算滑点 → 算可买手数 → 更新持仓均价(含费用摊薄) → 记成交
   - 卖出：检查 can_sell → 算滑点 → 全部卖出 → 算已实现盈亏 → 记成交
   - 持有：不动
5. 结算市值 mark_to_market
6. 计算奖励 _compute_reward
7. 推进 idx；到末尾则 terminated=True
8. 返回 (观测, 奖励, 是否结束, 是否截断, 信息字典)
```

### 账户状态（`account.py` 的 `EnvState`）
记录 `cash / shares / cost_basis / prev_close / last_buy_idx / portfolio_value / position_ratio` 等。其中：
- `portfolio_value = 现金 + 持仓股数 × 当前价`（市值估值）
- `position_ratio = 持仓市值 / 组合总市值`（仓位比例，用于奖励惩罚）
- `cost_basis`：持仓均价，卖出时用来算**已实现盈亏**

> 关键细节：多标的样本按日期拼接，代码用 `_build_prev_closes()` 和 `symbol_boundary` 保证**只在同一个标的内部**取「昨收」，新标的的第一天不会被误判为涨跌停——这是一个真实踩过的坑（跨标的昨收串味）。

## 4.4 A 股规则纯函数（rules.py）—— 把现实规则写进代码

**背景知识：A 股有哪些特殊交易规则？**
和美股 T+0 不同，A 股有独特规则，忽略它们会让回测严重失真：

| 规则 | 含义 | 代码实现 |
|---|---|---|
| **T+1** | 当天买入的股票，**下一个交易日**才能卖出 | `can_sell` 中 `held_days < 1` 拒绝 |
| **涨跌停** | 主板 ±10%、创业板/科创板 ±20%、北交所 ±30%，触板后**无法以该方向成交** | `is_limit_up` / `is_limit_down` |
| **停牌** | 当日无成交（或成交极低），不能交易 | `is_halted`（成交量极低判定） |
| **100 股整手** | 买卖必须是 100 股的整数倍 | `round_lots` / `max_affordable_lots` |
| **佣金** | 双边 0.025%，最低 5 元 | `trade_cost` |
| **印花税** | 仅卖出收 0.05% | `trade_cost`（sell 侧加收） |
| **滑点** | 成交价相对市价偏移 0.1%（模拟冲击成本） | `apply_slippage` |

### 买入被拒的典型原因（`_buy_block_reason`）
- 停牌 → 「停牌」
- 涨停 → 「涨停不可买入」
- 现金不足 → 「现金不足」

### 卖出被拒的典型原因（`_sell_block_reason`）
- 停牌 → 「停牌」
- T+1 冻结（当天买入）→ 「T+1 冻结」
- 跌停 → 「跌停不可卖出」
- 无持仓 → 「无持仓」

> 这些规则全部是**纯函数**，输入确定则输出确定，因此可以逐一写单元测试。比如「当天买入，当天卖」必须被 T+1 拒绝——这条就在测试覆盖里。

## 4.5 费用与滑点如何计算

`trade_cost(notional, side, commission_rate, stamp_tax_rate, min_commission)`：
- **买入**：`max(成交额 × 0.025%, 5元)`
- **卖出**：`max(成交额 × 0.025%, 5元) + 成交额 × 0.05%`（印花税仅卖出）

`apply_slippage(price, side, slippage)`：
- 买入价 = 市价 × (1 + 0.1%)
- 卖出价 = 市价 × (1 − 0.1%)

> 真实交易里你几乎永远无法以「恰好市价」成交（有冲击成本），滑点就是对此的保守建模。

## 4.6 奖励塑造（rewards.py）—— 怎么「教」AI 赚钱

**背景知识：奖励塑造（Reward Shaping）**
强化学习靠奖励信号学习。如果只给「最终赚了多少钱」一个稀疏奖励，模型很难学。所以通常把单步奖励设计成「即时收益 − 各种坏行为的惩罚」，引导模型朝我们想要的方向走。

本项目奖励公式（默认 `drawdown_penalty`）：
```
r = ret − λ₁·drawdown − λ₂·turnover − λ₃·|position_ratio|
```
- `ret`：本步组合收益率 `(value − prev_value) / prev_value`
- `drawdown`：当前相对历史峰值的回撤（跌得越深，惩罚越大）
- `turnover`：本步换手率（交易越频繁，惩罚越大，抑制过度交易）
- `|position_ratio|`：仓位比例（隐含对「满仓杠杆」的约束）

λ 系数在 `EnvConfig` 可调：`lambda_drawdown=0.1`、`lambda_turnover=0.001`、`lambda_leverage=0.01`。

### 支持的奖励类型（`SUPPORTED_REWARDS`）
| 类型 | 含义 |
|---|---|
| `gross` | 纯收益率，无惩罚 |
| `drawdown_penalty` | 默认，收益 − 回撤/换手/仓位惩罚 |
| `sharpe` | 单步夏普近似（收益/|收益|）− 成本项 |
| `excess` | **相对买入持有基准的超额收益** − 同类惩罚（把目标从「绝对赚钱」改成「跑赢懒人买入持有」）|

> `excess` 类型尤其值得注意：它衡量的是「比什么都不做（一直持有）强多少」，避免了「牛市里傻子都赚钱，模型也显得很厉害」的假象。

### 数值防御
奖励计算全程做 `np.isfinite` 检查，任何非有限分量（NaN/Inf）取 0，绝不产生 NaN 污染训练。

> `RewardCalculator` 在构造时就会校验 `reward_type` 是否在白名单，非法值抛 `ConfigError`，绝不静默降级。

## 4.7 观测与动作空间（spaces.py）

- `build_observation_space(n_features, window)`：声明观测形状 `(window, n_features)`，类型 float32。
- `build_action_space(mode)`：离散模式 → `Discrete(3)`（0/1/2）；连续模式 → `Box`（目标仓位 [0,1]）。

连续模式下，`_normalize_action` 把「目标仓位」与「当前仓位」比较：目标明显更高→买入，明显更低→卖出，否则持有（带 0.05 迟滞避免抖动）。

---

## 4.8 本篇小结

- 环境 = 强化学习的「舞台 + 裁判」：定义状态、动作、账户变化、奖励。
- A 股规则（T+1 / 涨跌停 / 停牌 / 整手 / 费用 / 滑点）全部实现为**纯函数**，可独立测试。
- 奖励通过「收益 − 回撤/换手/仓位惩罚」塑造，引导模型学出稳健、低换手、跑赢基准的策略。
- 多标的拼接时严格处理「昨收」与「标的分界」，避免跨标的套利失真。
